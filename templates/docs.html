Local business leads from Google Maps, with their emails

LocalLeads searches Google Maps for any kind of business in any country, saves every result to a database on this computer, and reads each business's website for emails, socials and phone numbers while the search runs.

1 · SearchPick what and where: "roofers" across Texas, every ZIP code in a city, or a list of places. 2 · EnrichWebsites are read for emails, socials and phones. Google place pages add reviews and owner details. 3 · UseFilter, browse and export a clean CSV or JSON, or let an AI agent do it for you over MCP.

Everything stays on this machine: no account, no cloud, no AI in the extraction. Pages are read and addresses pulled out by fixed rules, so results are repeatable.

Your first search in a minute

  1. Start the server and open the app (it runs at http://127.0.0.1:7878). The first time, create your account with an email and password.
  2. Click New search. Start typing what you're looking for, like plumb, and pick Plumber from the list.
  3. Pick a place under Where?: a country, then a state, a few cities or ZIP codes.
  4. Leave Find emails ticked under Extras and press Start search.
  5. Leads appear within seconds. Open Leads to browse and export them.
Start the server from a terminal
localleads --open

Useful options: --db PATH uses another database file, --bind 127.0.0.1:7879 picks another port.

Signing in

The first time LocalLeads opens a database, it asks for an email and a password (twice) and creates the one account for that database. After that, you sign in with them. Each sign-in lasts 30 days on that browser.

  • Sign out is in the Account menu at the bottom of the sidebar, and on Settings.
  • Change password on Settings: enter the current one and the new one twice. Every other browser is signed out; API keys keep working.
  • There's no password reset and no second account. If you lose the password, start over with a new database file (--db), or restore a backup made before the password changed.

The password is stored as an Argon2 hash. Sign-in tokens and API keys are stored only as hashes, so a copy of the database can't be used to sign in.

Setting up a search

What and where

  • What are you looking for? Start typing and pick from the categories Google Maps itself uses, like Roofing contractor or Dentist; closest matches come first. The Groups tab lists them by industry, with Select all for a whole group. Anything else, like a brand name, press Enter to search for it exactly as typed. You can also paste a list. Each one is searched in every area.
  • Where? Pick any country, then the whole country, some states or provinces, single cities, ZIP or postal codes, or type your own places. Google only shows about 120 results per lookup, so a big area is split into smaller ones (Split into ZIP codes, cities or whole states) and searched busiest first, to get as many as Google Maps has.

How many

  • Stop after ends the search once that many new leads are saved. No limit gets everything Google Maps has.
  • Leads already in your database aren't saved twice. They count as repeats skipped, which is normal when areas overlap.

Extras for each lead

  • Find emails reads up to 8 pages of each website: the home page, then contact, about and team pages. Socials, phones and site details come with it.
  • Open the Google place page adds reviews per star, review topics, owner and photos.

  • Verify emails asks each email's mail server whether the address exists. It's slower and off by default. Found emails show up right away either way.

Speed and proxies

Requests at once sets how many Google lookups run at the same time. Without proxies keep it around 10, or Google starts refusing requests. With a few hundred healthy proxies, 100 to 300 works. Proxy group limits the search to one group of proxies.

Under Advanced you can name the search, search by Google Maps URL or place ID instead of text, add filters (rating, reviews, has website and more), change the language and region, and set retries.

Live progress

The progress card has two halves:

  • Google Maps: new leads saved out of the target, then areas searched out of the total and repeats skipped (businesses already in your database).
  • Websites: sites read so far, how many had an email, the reading speed and about how long is left. Leads that another search already read count straight away.

The Activity tab is the search's log: every step, retry and failure, with a filter and a download. Setup shows exactly what the search was started with.

  • Pause and Resume hold a search without losing anything.
  • Stop ends it and keeps every lead. Continue carries on later from where it stopped: areas it already finished are skipped.
  • Run again (in the ⋯ menu) starts a fresh copy with the same settings. Duplicate and edit opens a copy in the form first.
  • If the server restarts, updates or crashes, running searches carry on by themselves from the areas they'd finished once it's back.

Browsing, filtering and exporting

Leads is one table of every lead. The Search filter narrows it to one or more searches; Open leads on any search takes you straight there.

  • Filters: search, category, state, city, has phone or website, email found or not, and rating. Each shows how many leads match. Combine as many as you like.
  • Search box: matches name, address, phone, website and email.
  • Select rows, or Select all to take every lead that matches, then export them, delete them, or run Find emails again. A delete can be undone from its notice for an hour.
  • Columns picks what the table shows.
  • Export downloads everything that matches the filters. Download CSV gives the clean layout: one row per business, readable column names, best email first, opening hours written out and a Google Maps link. Choose CSV columns… lets you drop columns, or switch to the Outscraper format (raw fields, one row per email) for tools that expect it. JSON keeps the raw Google Maps data. Save CSV and JSON next to the database writes big exports straight to disk.

How emails are found{% if can_verify %} and checked{% endif %}

For each lead with a website, LocalLeads reads the home page, follows links that look like contact, about or team pages, and tries common paths like /contact if nothing turns up. It picks up:

  • mailto: links, plain-text addresses and ones hidden with [at] or (dot)
  • Cloudflare-protected addresses and emails in structured data
  • Names and job titles next to an address, from team pages
  • Facebook, Instagram, LinkedIn, X, YouTube and TikTok links, extra phone numbers, the site's title, and Google Tag Manager and Facebook Pixel usage

The best email for each lead is one on the company's own domain, with a person's address ahead of a role address like info@.

{% if can_verify %}

Verification (optional)

Tick Verify emails on a search to ask each address's mail server whether it exists. LocalLeads checks the 5 best emails per lead, without sending any mail. Verdicts:

  • Safe: the server confirmed the mailbox.
  • Risky: it exists but accepts everything (catch-all), or it's a role or throwaway address.
  • Unverified: the server wouldn't say. Microsoft 365 and Yahoo often refuse checks from home connections.
  • Invalid: the server said no such mailbox. Invalid emails never become the lead's best email.

Checks need outgoing port 25, which many home and cloud networks block. SOCKS5 proxies that allow port 25 are used for checks when you have them.

{% endif %}

Proxies for bigger searches

Google limits how fast one connection can search. Proxies spread the lookups out, so you can run many more at once. Paste them one per line:

Accepted formats
http://user:pass@host:8080
socks5://user:pass@host:1080
host:3128
  • Check tests every proxy against Google Maps and marks it healthy, slow or failed.
  • Groups let a search use only some proxies, like a residential set.
  • A proxy that fails during a search is set aside, and the request is retried through another one.
  • Only Google lookups go through proxies. Websites are always read from your own connection.

Run LocalLeads from Claude, Codex, Cursor and more

LocalLeads includes an MCP server, so an AI agent can start searches, check progress, filter leads and export them in plain language. The Agents page has the exact setup for each agent, with your paths filled in.

Agents need an API key. Create one under API keys on the Agents page (one per agent or machine is easiest) and copy it straight away: it's shown only once. The setup snippets on that page fill the new key in for you. Agents that launch LocalLeads pass it in the LOCALLEADS_API_KEY environment variable; agents that connect over HTTP send it as Authorization: Bearer <key>. Revoke a key there and agents using it stop working at once.

{{ install }}

Then ask, for example: "Find 300 dentists in Denver with emails and export them to CSV." Agents get every tool the dashboard has, {{ tool_count }} in all: searches and categories, leads and exports, proxies and groups, backups, the server log, and undoing a delete.

Your data and backups

Everything (searches, leads and proxy credentials) is in one SQLite file. Download a backup takes a consistent copy even while searches run. To restore, stop the server and start it with --restore /path/to/backup.sqlite. Keep the file private, because it holds your proxy logins.

Server log and updates

System shows the server's own log since it started: searches, proxy checks, website reading, warnings and errors, live as they happen. Filter it by level, search it, or download it to share when something goes wrong.

LocalLeads checks GitHub for new versions once in a while. When one is out, an Update and restart card appears in the sidebar: it downloads the release, checks it against the release's checksums, backs up your database and restarts. Running searches pause for a few seconds and carry on afterwards. Check for updates in the Account menu looks right away. Start the server with LOCALLEADS_UPDATES=off to turn checks off.

Common questions

I don't see any emails yet

Emails come from websites, so leads without a website never get one. Websites are read once Google Maps is done, and the with an email count under Websites goes up as sites are read. About half of local businesses publish an email on their site.

Google stopped returning results or the search got slow

Google is limiting your connection. Stop the search, lower Requests at once to about 10 (or add proxies), and use Continue to carry on where it stopped.

So many "repeats skipped". Is that normal?

Yes. Neighbouring areas overlap, and the same business shows up in several lookups. Each one is saved once and listed under every search that found it.

A website shows as failed

The site was down, too slow (over 30 seconds) or its domain no longer exists. The lead keeps its Google details; select it in Leads and use Find emails to try again later.

I deleted something by mistake

Deleted searches, leads, proxies and groups are kept for an hour. Click Undo on the notice that appeared, or ask your agent to undo it.

"Address already in use" when starting

Another copy is already running on port 7878. Open http://127.0.0.1:7878, or stop it first, or start this one with --bind 127.0.0.1:7879.

My agent can't connect over MCP

Restart the agent after adding the config, and check that the command on the Agents page still exists. Over HTTP, the app has to be running.

My agent says "needs an API key" or "invalid or revoked API key"

The agent's config has no key, or one that was revoked or mistyped. Create a new key on the Agents page and put it in the agent's config (LOCALLEADS_API_KEY for a command, the Authorization header over HTTP), then restart the agent.

I forgot my password

There's no reset. Your leads are still in the database file, but the app needs the password. Start with a new database (--db new.sqlite), or restore a backup from before the password changed.
