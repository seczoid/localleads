Overview

Local business leads from Google Maps, with their emails

LocalLeads searches Google Maps for any kind of business in any area, saves every result to a database on this computer, and reads each business's website for emails, socials and phone numbers while the search runs.

1 · SearchPick what and where: "roofers" across Texas, every ZIP code in a city, or a list of places. 2 · EnrichWebsites are read for emails, socials and phones. Google place pages add reviews and owner details. 3 · UseFilter, browse and export to CSV or JSON, or let an AI agent do it for you over MCP.

Everything stays on this machine: no account, no cloud, no AI in the extraction. Pages are read and addresses pulled out by fixed rules, so results are repeatable.

Quick start

Your first search in a minute

  1. Start the server and open this dashboard (it runs at http://127.0.0.1:7878). The first time, create your account with an email and password.
  2. Click New search. Type what you're looking for, like plumbers.
  3. Pick a place under Where?, a state, a few cities or ZIP codes.
  4. Leave Find emails ticked and press Start search.
  5. Leads appear within seconds. Open Leads to browse and export them.
Start the server from a terminal
localleads --open

Useful options: --db PATH uses another database file, --bind 127.0.0.1:7879 picks another port.

Your account

Signing in

The first time LocalLeads opens a database, it asks for an email and a password (twice) and creates the one account for that database. After that, you sign in with them. Each sign-in lasts 30 days on that browser.

  • Sign out is at the bottom of the sidebar, and on Settings.
  • Change password on Settings: enter the current one and the new one twice. Every other browser is signed out; API keys keep working.
  • There's no password reset and no second account. If you lose the password, start over with a new database file (--db), or restore a backup made before the password changed.

The password is stored as an Argon2 hash. Sign-in tokens and API keys are stored only as hashes, so a copy of the database can't be used to sign in.

New search

Setting up a search

What and where

  • What are you looking for? One kind of business per line. Each one is searched in every area.
  • Where? Pick a country, then whole states, single cities, ZIP codes, or type your own places. Google only shows a limited number of results per lookup, so a big area is searched ZIP code by ZIP code, busiest first, to get as many as Google Maps has.

How many

  • Maximum results stops the search once that many new leads are saved. No limit gets everything Google shows.
  • Leads already in your database aren't saved twice. They count as repeats skipped, which is normal when areas overlap.

Enrich each lead

  • Find emails reads up to 8 pages of each website: the home page, then contact, about and team pages.
  • Google place page adds reviews per star, review topics, owner and photos.

  • Verify emails asks each email's mail server whether the address exists. It's slower and off by default. Found emails show up right away either way.

Proxies and speed

Requests at once sets how many Google lookups run at the same time. Without proxies keep it around 10, or Google starts refusing requests. With a few hundred proxies, 100 to 300 works. Websites are always read directly and quickly, 64 at a time, whatever you set here.

Under Advanced you can name the search, add filters (rating, reviews, has website and more), change the language and choose the columns to export.

Watching a search

Live progress

The blue line under the title reads like this:

  • 12 of 40 areas searched means Google lookups done out of the total.
  • 860 leads means new businesses saved so far.
  • 700 enriched means leads whose website and place page have been read.
  • 420 with email means leads where at least one email was found.
  • checking emails of 35 only appears when verification is on. It counts leads waiting for their mail-server check.

Websites are read alongside the Google search, so emails appear while it's still collecting. When the server restarts, a running search is marked interrupted. Use Run again to start it over; leads you already have are skipped.

Leads

Browsing, filtering and exporting

Leads shows one card per search. Open one, or All leads, to get the table.

  • Filters: search, category, state, city, has phone or website, email found or not, and rating. Each shows how many leads match. Combine as many as you like.
  • Search box: matches name, address, phone, website and email.
  • Select rows to export them, delete them, or run Find emails again.
  • Export downloads CSV or JSON for everything that matches the filters, or writes big exports straight to disk.
Emails

How emails are found{% if can_verify %} and checked{% endif %}

For each lead with a website, LocalLeads reads the home page, follows links that look like contact, about or team pages, and tries common paths like /contact if nothing turns up. It picks up:

  • mailto: links, plain-text addresses and ones hidden with [at] or (dot)
  • Cloudflare-protected addresses and emails in structured data
  • Names and job titles next to an address, from team pages
  • Facebook, Instagram, LinkedIn, X, YouTube and TikTok links, extra phone numbers, the site's title, and Google Tag Manager and Facebook Pixel usage

The best email for each lead is one on the company's own domain, with a person's address ahead of a role address like info@.

{% if can_verify %}

Verification (optional)

Tick Verify emails on a search to ask each address's mail server whether it exists. LocalLeads checks the 5 best emails per lead, without sending any mail. Verdicts:

  • Safe: the server confirmed the mailbox.
  • Risky: it exists but accepts everything (catch-all), or it's a role or throwaway address.
  • Unverified: the server wouldn't say. Microsoft 365 and Yahoo often refuse checks from home connections.
  • Invalid: the server said no such mailbox. Invalid emails never become the lead's best email.

Checks need outgoing port 25, which many home and cloud networks block. SOCKS5 proxies that allow port 25 are used for checks when you have them.

{% endif %}
Proxies

Proxies for bigger searches

Google limits how fast one connection can search. Proxies spread the lookups out, so you can run many more at once. Paste them one per line:

Accepted formats
http://user:pass@host:8080
socks5://user:pass@host:1080
host:3128
  • Check tests every proxy against Google Maps and marks it healthy, slow or failed.
  • Groups let a search use only some proxies, like a residential set.
  • A proxy that fails during a search is set aside, and the request is retried through another one.
  • Only Google lookups go through proxies. Websites are always read from your own connection.
AI agents (MCP)

Run LocalLeads from Claude, Codex, Cursor and more

LocalLeads includes an MCP server, so an AI agent can start searches, check progress, filter leads and export them in plain language. The MCP page has the exact setup for each agent, with your paths filled in.

Agents need an API key. Create one under API keys on the MCP page (one per agent or machine is easiest) and copy it straight away: it's shown only once. The setup snippets on that page fill the new key in for you. Agents that launch LocalLeads pass it in the LOCALLEADS_API_KEY environment variable; agents that connect over HTTP send it as Authorization: Bearer <key>. Revoke a key there and agents using it stop working at once.

The quickest way sets up Claude Code, Codex and Cursor in one go, with a new key:

Run in a terminal
{{ install }}

Then ask, for example: "Find 300 dentists in Denver with emails and export them to CSV."

Backups

Your data and backups

Everything (searches, leads and proxy credentials) is in one SQLite file. Download a backup takes a consistent copy even while searches run. To restore, stop the server and start it with --restore /path/to/backup.sqlite. Keep the file private, because it holds your proxy logins.

Troubleshooting

Common questions

I don't see any emails yet

Emails come from websites, so leads without a website never get one. Reading starts a few seconds after leads come in, and the with email count in the progress line goes up as sites are read. About half of local businesses publish an email on their site.

Google stopped returning results or the search got slow

Google is limiting your connection. Lower Requests at once to about 10, or add proxies and pick their group in the search.

So many "repeats skipped". Is that normal?

Yes. Neighbouring areas overlap, and the same business shows up in several lookups. Each one is saved once and listed under every search that found it.

A website shows as failed

The site was down, too slow (over 30 seconds) or its domain no longer exists. The lead keeps its Google details; select it in Leads and use Find emails to try again later.

Where is email verification?

This copy was built without it. Build with cargo build --release --features verify to add the Verify emails option to searches.

"Address already in use" when starting

Another copy is already running on port 7878. Open http://127.0.0.1:7878, or stop it first, or start this one with --bind 127.0.0.1:7879.

My agent can't connect over MCP

Restart the agent after adding the config, and check that the command on the MCP page still exists. Over HTTP, the dashboard has to be running.

My agent says "needs an API key" or "invalid or revoked API key"

The agent's config has no key, or one that was revoked or mistyped. Create a new key on the MCP page and put it in the agent's config (LOCALLEADS_API_KEY for a command, the Authorization header over HTTP), then restart the agent.

I forgot my password

There's no reset. Your leads are still in the database file, but the dashboard needs the password. Start with a new database (--db new.sqlite), or restore a backup from before the password changed.
